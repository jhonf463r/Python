WHO CONSUMES THE OUTPUTS
------------------------

1. ScenarioRunRepository
   - Saves ScenarioRun objects
   - Provides query methods for scenario runs
   - Used by ScenarioAutoTestService

2. ExecutionDossierRepository
   - Updated with scenario_run_id, probe_diagnosis, runtime_adjustments
   - Updated with self_teach metadata
   - Used for execution tracking

3. TaskOutcomeRecorder
   - Records updated AdaptiveSession
   - Persists to AdaptiveSessionRepository
   - Updates learning metadata

4. PendingIssueService
   - Enqueues pending issues for NEED_ADAPTER or NEED_CODEX_FIX
   - Creates CodexPendingIssue objects
   - Used for self-improvement task generation

5. RuntimeTuner
   - Evaluates diagnosis and applies runtime adjustments
   - Modifies session behavior based on test results
   - Used for dynamic runtime optimization

6. UI/ControlCenter
   - Displays test results to user
   - Shows pending issues from test failures
   - Allows manual intervention

---

WHETHER OUTPUTS CHANGE LATER BEHAVIOR
-------------------------------------

YES - Test outputs change behavior:

1. Diagnosis category changes behavior:
   - NEED_ADAPTER: enqueues pending issue for adapter creation
   - NEED_CODEX_FIX: enqueues pending issue for Codex fix
   - Other categories: no pending issue, just recording

2. Runtime adjustments change behavior:
   - Applied to session immediately
   - Modify subsequent execution behavior
   - Can change timeouts, retries, etc.

3. Pending issues change behavior:
   - Appear in PlatformPendingQueue
   - Surface in startup_summary()
   - Require manual or automatic resolution

4. ScenarioRun status changes behavior:
   - FAILED: may trigger retry or remediation
   - COMPLETED: marks scenario as successful
   - ABORTED: may trigger investigation

5. CapabilityReadiness updates:
   - episode_id updated with latest scenario run
   - Affects future routing decisions
   - Influences tool selection

---

CONCLUSION
----------

Test execution loop EXISTS but is LIMITED:
- ScenarioAutoTestService runs scenario-based tests
- run_pytest runs pytest test suite
- Test results are recorded in repositories
- Test results can generate pending issues
- Test results can apply runtime adjustments
- Tests are NOT automatically run on a schedule
- Test results are NOT automatically used for self-improvement
- NO continuous integration or test-driven development loop

The system can RUN tests and RECORD results but cannot AUTONOMOUSLY USE test results for self-improvement.
