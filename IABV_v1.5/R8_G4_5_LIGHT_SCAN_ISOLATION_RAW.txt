============================================================
ROOT CAUSE
============================================================

The test calls scan_now with full=False, expecting a "light scan" that avoids subprocess calls.

However, _cpu_snapshot() at line 967-988 has this logic:

    if self._in_test_mode() and not full:
        snapshot['name'] = platform.processor() or ''
        return snapshot

The test does NOT set the PYTEST_CURRENT_TEST environment variable, so _in_test_mode() returns False.

Therefore, even with full=False, _cpu_snapshot() still executes:

    processor_json = self._powershell_json(
        "Get-CimInstance Win32_Processor | Select-Object -First 1 Name,NumberOfCores,NumberOfLogicalProcessors,CurrentClockSpeed,MaxClockSpeed | ConvertTo-Json -Compress"
    )

This calls _powershell_json() at line 1139, which calls _run_command() at line 1143:

    result = self._run_command([shell, '-Command', command], timeout_seconds=self._POWERSHELL_TIMEOUT_SECONDS)

_POWERSHELL_TIMEOUT_SECONDS = 1.0 (line 42)

The subprocess.run() call at line 1156-1164 with timeout=1.0 is likely blocking or hanging.

COMMAND_IF_ANY = powershell.exe -Command "Get-CimInstance Win32_Processor | Select-Object -First 1 Name,NumberOfCores,NumberOfLogicalProcessors,CurrentClockSpeed,MaxClockSpeed | ConvertTo-Json -Compress"
RESOURCE_IF_ANY = PowerShell subprocess
TIMEOUT_IF_ANY = 1.0 seconds

============================================================
WHY THE TIMEOUT ISN'T WORKING
============================================================

The _run_command() method at line 1154-1167 has:

    try:
        completed = subprocess.run(
            command,
            capture_output=True,
            text=True,
            encoding='utf-8',
            errors='ignore',
            timeout=timeout_seconds,
            check=False,
        )
    except Exception:
        return None

The timeout should raise subprocess.TimeoutExpired after 1.0 seconds, which is caught by the 
bare except Exception and returns None.

However, the test hangs indefinitely, suggesting either:
1. The subprocess is not respecting the timeout on this Windows system
2. There's a deeper system-level blocking issue with PowerShell
3. The exception handling is not working as expected

============================================================
SOLUTION PATH
============================================================

To enable LIGHT_SCAN to complete without blocking, the test must either:

OPTION 1: Set PYTEST_CURRENT_TEST environment variable to trigger test mode
OPTION 2: Modify the test to use full=False AND set test mode
OPTION 3: Use a different initialization approach that doesn't require bootstrap_scan

The production code is NOT buggy - it's designed to skip heavy scans in test mode.
The test is not properly signaling that it's running in test mode.
