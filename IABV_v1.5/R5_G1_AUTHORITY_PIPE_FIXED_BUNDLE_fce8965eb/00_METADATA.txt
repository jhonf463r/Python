## Issue Summary
The G1 E2E test was failing with "Failed to connect to authority pipe after 30 attempts" during REGISTER_EXECUTION. The root cause was a race condition where the test fixture was creating an AuthorityClient connection before tool registration, which conflicted with the acquire_capability_for_execution call that also creates its own connection.

## Root Cause
1. The G1 test fixture was initializing AuthorityClient before calling g1_goal_to_protected_tool
2. The g1_goal_to_protected_tool method calls acquire_capability_for_execution, which creates its own AuthorityClient
3. When the first connection was still holding the pipe, the second connection attempt failed with ERROR_PIPE_BUSY
4. Additionally, the CapabilityActionBridge was not properly initialized with a connected AuthorityClient for lease consumption

## Investigation Findings
- Authority process lifecycle: Working correctly (started, alive, pipe created, ready)
- C2 test pattern: Works correctly because it calls acquire_capability_for_execution first, then creates a new AuthorityClient for CapabilityActionBridge
- G1 test pattern: Was attempting to pre-connect AuthorityClient, causing pipe busy race condition
- Tool selection: CloudReasoningPlannerService was assigning unsupported tools (chatgpt, devin) instead of write_repo_file

## Fixes Applied

### 1. Authority Pipe Connection Fix (src/iabv_v15/infra/mcp/server.py)
- Added capability_bridge_setup step in g1_goal_to_protected_tool after acquire_capability_for_execution
- This step creates a fresh AuthorityClient for CapabilityActionBridge after the capability acquisition closes its connection
- Follows the C2 test pattern to avoid pipe busy race condition

### 2. Dynamic Bridge Lookup (src/iabv_v15/infra/mcp/self_update_tools.py)
- Added container parameter to register_self_update_tools for dynamic bridge lookup
- Added _get_capability_action_bridge() helper to look up bridge from container
- Modified write_repo_file to accept optional lease_id parameter for G1 flow
- G1 flow: Uses lease_id from acquire_capability_for_execution (bypasses acquire_capability_for_existing_execution)
- C2 flow: Acquires new lease via acquire_capability_for_existing_execution (existing behavior)

### 3. Tool Selection Fix (src/iabv_v15/services/adaptive/cloud_reasoning_planner.py)
- Refined _PLAN_SYSTEM_PROMPT to explicitly instruct planner to use write_repo_file for file operations
- Added clear instructions to avoid using chatgpt, devin, or other LLM tools for file mutations
- Emphasized that only write_repo_file is executable for file operations

### 4. Test Fixture Fix (tests/windows_e2e/test_g1_goal_to_protected_tool.py)
- Removed early AuthorityClient initialization from test fixture
- Let g1_goal_to_protected_tool handle AuthorityClient lifecycle internally
- Fixed governance_fn signature to accept **kwargs
- Added runtime data capture for forensic bundle

### 5. Conftest Fix (tests/windows_e2e/conftest.py)
- Removed pipe availability check that was causing race conditions
- Simplified to just wait for process initialization
