## Issue Summary
The independent audit of commit 301d84bd4 found that the G2 positive test was passing with verification_failed, which violates strict verification semantics. The audit also identified that the expected_result hash was being guessed by the LLM instead of calculated deterministically from plan parameters.

## Root Cause Analysis
1. The planner was instructed to include cryptographic hashes in expected_result, causing the LLM to guess hash values
2. The verification logic accepted substring matching for hashes, allowing incorrect hashes to pass
3. The G2 positive test did not enforce strict verification semantics (it accepted verification_failed as "expected behavior")
4. The G2 positive test used a literal goal that specified target/content, reducing planning autonomy

## Fixes Applied

### 1. Deterministic Hash Derivation (src/iabv_v15/infra/mcp/server.py)
- Calculate expected hash deterministically from plan parameters (content field)
- Ignore LLM-generated hash fields (content_hash, file_hash_sha256) in expected_result
- Copy only semantic expectations (file_exists, content_contains) from plan expected_result
- Add file content to observed_result for semantic verification
- Add content_contains comparison logic (substring matching)
- Require exact match for hash comparison (no substring matching)
- Track hash_derivation method in trace ('deterministic_from_plan_parameters')

### 2. Planner Prompt Update (src/iabv_v15/services/adaptive/cloud_reasoning_planner.py)
- Instruct planner NOT to include cryptographic hashes in expected_result
- Instruct planner to use semantic expectations (file_exists, file_size, content_contains)
- Separate LLM reasoning (what should happen) from deterministic derivation (exact hash)

### 3. G2 Positive Test Update (tests/windows_e2e/test_g2_goal_to_action_plan.py)
- Use abstract goal: "Create a small diagnostic marker file in the workspace root to record this G2 execution timestamp"
- Goal does NOT specify exact target/content - planner decides
- Add strict verification assertion: result_verification.status == 'verified'
- Add strict verification assertion: mismatches == []
- Add hash_derivation assertion: 'deterministic_from_plan_parameters'
- Add HUMAN_INPUT_FIELDS and PLAN_DERIVED_FIELDS tracking
- Clean up existing test files before test to ensure git status changes

### 4. G2 Negative Test Verification
- Verify negative test still passes with verification_failed detection
- Verify negative test detects mismatches correctly
- Verify action executes successfully but verification fails
