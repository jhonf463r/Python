# CHAT-ARCH-2026-10-08-174 — IABV FRAME ACTIVATION + EXPERIENCE-DRIVEN TASK CONSTRUCTION

## PURPOSE

Strengthen cross-chat IABV continuity after the RQ21.55 Deep Research failure.

The repository already contains the necessary memory, evidence and routing organs. The missing operational constraint was not another memory store or another coordinator organ. The missing constraint was:

**use the relevant accumulated IABV experience BEFORE constructing the next task/prompt.**

A new chat must therefore temporarily enter the IABV canonical frame before substantive IABV work.

This is a cognitive/coordination protocol, not a claim that the IABV runtime already performs autonomous cross-chat context activation.

## CORE RULE

For any material IABV objective:

`new objective → IABV frame activation → experience retrieval → current-truth reconciliation → closed-edge reconstruction → first-open-edge detection → capability/actor/readiness analysis → task/prompt construction → execution → verification → reconciliation → writeback`

Never use:

`user context dump → previous prompt → next prompt`

and never use:

`long historical memory → generic reasoning → plausible task`.

## 1. FRAME ACTIVATION IS MANDATORY BEFORE PROMPT CONSTRUCTION

Before generating a prompt for Deep Research, Sonnet, Codex, Devin or another actor, the coordinating AI must establish:

1. current remote `main` provenance;
2. current canonical state/routing snapshot;
3. objective-conditioned historical memory;
4. prior relevant failures and false positives;
5. relevant negative knowledge;
6. applicable methodology/protocol deltas;
7. existing IABV organs/mechanisms that may already own the capability;
8. the first still-open causal/evidential edge;
9. required capability;
10. actor fit and execution/readiness constraints.

Only then may it construct the external task.

## 2. FOUR-LAYER EXPERIENCE ACTIVATION

The activated context must be assembled in this order:

### A. CURRENT TRUTH

What is verified now?

Source priority:

`current source/runtime evidence > current canonical reconciliation > historical claim > transcript claim`

### B. RELEVANT EXPERIENCE

What has IABV already learned about this class of problem?

Retrieve only material records containing:
- prior failed attempts;
- false-positive patterns;
- successful discriminating methods;
- rejected alternatives;
- known contradictions;
- actor-specific lessons;
- prompt-construction lessons;
- evidence/readiness lessons.

### C. NEGATIVE KNOWLEDGE

What must not be repeated?

Examples:
- wrong-object research;
- document-centric drift;
- generic replacement when an input is missing;
- invented current architecture;
- treating report quality as task compliance;
- treating a citation as source verification;
- inheriting historical NEXT ACTOR;
- routing from message count or previous prompt;
- calling an implementation actor before readiness.

Negative knowledge is an active constraint, not passive history.

### D. METHOD DELTA

Which prior lesson changes HOW the present task must be performed?

For Deep Research, this includes:
- unique EXECUTION_ID and OBJECT_ID;
- literal OBJECT LOCK;
- explicit IN/OUT scope;
- primary-source strategy;
- required result signature;
- stop conditions;
- object-first adjudication;
- source/evidence audit before absorption.

A prior method lesson is useful only when it changes the current construction.

## 3. EXPERIENCE MUST CHANGE THE PROMPT

A retrieved historical lesson must be compiled into an explicit constraint when it is materially relevant.

Example:

Prior failure:
`research request → generic Deep Research/meta report`

Current prompt consequence:
`OUT OF SCOPE: researching Deep Research itself, research methodology, generic architecture, generic security, project management`

Prior failure:
`researcher invents current IABV architecture`

Current prompt consequence:
`Stage A external research only; do not infer current IABV architecture; repository reconciliation is a separate stage`

Prior failure:
`generic report accepted because it was detailed`

Current prompt consequence:
`OBJECT TARGET GATE precedes source quality, citation count and report completeness`

Therefore:

**memory is not merely context copied into the prompt; memory must become task constraints, falsification controls and acceptance gates.**

Before constructing an actor prompt, produce an internal compact packet:

This packet is temporary working context. It is not a new persistent IABV organ.

## 5. DEEP RESEARCH SPECIALIZATION

For every new Deep Research execution:

`IABV frame activation
→ research object lock
→ experience-derived prompt constraints
→ unique execution identity
→ bounded research threads
→ result signature
→ object-target gate
→ coverage gate
→ source/evidence gate
→ reconciliation
`

Do not treat the mere existence of a prior successful-looking prompt as proof that the prompt construction method was followed.

A prompt must be reconstructed from the current objective and the accumulated lessons.

## 6. RESULT RECONSTRUCTION IS ALSO EXPERIENCE-DRIVEN

When a result arrives, do not evaluate it in isolation.

Compare it with:
- the exact execution contract;
- known failure modes for that task class;
- prior false positives;
- current IABV state;
- expected evidence boundary.

Then compute:

`WHAT WAS KNOWN BEFORE → WHAT THE RESULT ADDS → WHAT IT CONTRADICTS → WHAT REMAINS UNPROVEN → HOW THE METHOD CHANGES → WHETHER ROUTING CHANGES`

## 7. NO NEW "MEGA-MIND" ORGAN

This method explicitly rejects creating a new universal `ResearchBrain`, `MemoryBrain`, `ContextCore`, `CoordinatorBrain` or equivalent.

The existing IABV organs already provide the required functions:

- `CURRENT-STATE.md` — current routing authority;
- `CONTEXT-INDEX.md` — objective-conditioned retrieval;
- `MEMORY-OPERATING-PROTOCOL.md` — retrieval/epistemic discipline;
- `SYMBIOSIS-MAP.md` — cross-actor capability/learning transfer;
- `UNRESOLVED-KNOWLEDGE.md` — unresolved and negative knowledge;
- `ARCHIVE-REGISTRY.md` — provenance navigation;
- historical source records — detailed evidence and experience.

The "IABV mind" in a new chat is therefore a **temporary composition of existing knowledge/control organs**, not a new subsystem.

## 8. USER COORDINATION REDUCTION

When the repository contains the relevant durable knowledge, the user should not have to repeat:
- why a previous attempt failed;
- which prompt patterns are already known to fail;
- which claims are closed;
- which actor was previously used;
- what negative knowledge must be preserved.

The coordinating AI must retrieve and apply those lessons itself.

The user remains necessary for new objectives, normative decisions and information unavailable to the canonical layer.

## 9. EPISTEMIC STATUS

The following are distinct:

`frame activation = operational reasoning method`

`frame activation ≠ proof that IABV runtime autonomously activated context`

`memory retrieval ≠ causal learning`

`prompt adaptation ≠ evidence that the external actor learned`

`repository continuity ≠ autonomous runtime continuity`

The stronger developmental claim remains:

`verified experience → reusable knowledge/method → later decision change → observable consequence`

## 10. REQUIRED FUTURE CHAT BEHAVIOR

When a new chat receives an IABV objective, it should silently perform:

`ENTER IABV FRAME
→ verify current GitHub state
→ retrieve objective-relevant memory
→ recover prior experience and negative knowledge
→ reconcile current truth
→ locate first open edge
→ determine capability and readiness
→ construct the task/prompt from that evidence
`

It should not ask the user to restate durable knowledge that is already reachable in GitHub unless access to that knowledge is genuinely unavailable.
