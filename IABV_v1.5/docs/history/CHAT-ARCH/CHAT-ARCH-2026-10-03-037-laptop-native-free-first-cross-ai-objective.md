# CHAT-ARCH-2026-10-03-037 — Laptop-Native / Free-First / Cross-AI Objective

## PURPOSE
Canonicalize the broader product objective and operating constraint that must remain active across chats so local experiments do not drift toward a narrower 'IABV ↔ Codex' objective.

## OVERARCHING PRODUCT OBJECTIVE
IABV is intended to become a laptop-native operational assistant/coordinator: the laptop, its installed applications, human-used browsers/sessions, desktop/UI, local runtime, available accounts/resources, and external AI tools should be treated as one operational environment coordinated through existing IABV capabilities.

Preserve the distinction:
`capability ≠ realization`
A browser, desktop app, local model, MCP server, installed tool, web session or external AI is a realization of a capability, not a separate algorithmic brain.

## CROSS-AI OBJECTIVE
The desired collaboration is not simply 'connect IABV to Codex'. The target is:
`IABV current state/memory → capability/realization selection → appropriate external AI/tool → execution → observation → verification → result ingestion → reusable delta → changed future decision`

Codex and ChatGPT are cooperating realizations within this larger laptop-native IABV environment. Actor selection must remain objective/capability-fit, not product loyalty or fixed sequencing.

## ECONOMIC / RESOURCE CONSTRAINT
Current operating condition: **FREE-FIRST / NO NEW PAID API KEYS OR SUBSCRIPTIONS** unless the user explicitly changes this constraint.

Priority order for experiments and implementations:
1. existing local capabilities and installed applications;
2. free-tier capabilities already available to the user;
3. existing web-session/browser access and existing accounts;
4. local providers/models such as Ollama when capability-fit;
5. only then discuss paid infrastructure, and never treat purchase as the default unblocker.

Do not recommend buying an API key, paid proxy, paid cloud environment or new subscription as a routine way to move a frontier forward.

## CURRENT FREE TOOLING FACTS
Current OpenAI documentation states Codex is included in ChatGPT Free and Go, with usage limits; Codex Cloud is not included in Free/Go. Therefore Codex can remain a primary free-first development actor without requiring an OpenAI API key, subject to its usage limits.

Current OpenAI documentation also states full custom MCP support in ChatGPT is rolling out for Business, Enterprise and Edu. Therefore direct ChatGPT custom-MCP integration must not be treated as a Free-plan prerequisite.

## LAPTOP CAPABILITY TARGET
The intended laptop assistant must progressively reason across:
- installed applications / desktop UI;
- the human's actual browser/session, where governed access exists;
- isolated browser capabilities when appropriate;
- local runtime and filesystem;
- local/free models and providers;
- external AI agents such as Codex;
- accounts, authentication, authorization and resource state;
- temporal freshness and environment state.

Existing IABV evidence already includes UniversalPerceptionService, UIExecutionRunner, shared-CDP/browser pathways, WorldModel/EnvironmentSelfModel, capability/readiness components, MCP server tools and local-provider paths. Their universal causal composition remains to be proven; do not infer completion from existence.

## SPACE-TIME / CONTINUITY REQUIREMENT
Material human statements, environmental constraints, decisions, verified results and routing changes must be recorded as time-indexed evidence with objective/phase/context, provenance, status, and supersession where applicable.

Do not store every conversational sentence indiscriminately. Preserve decision-relevant state changes and circumstances so a later AI can reconstruct:
`what was wanted → what was true then → what changed → why a route was chosen → what happened → what remains open`.

Temporal records must not automatically become current routing authority. Only the canonical CURRENT-STATE snapshot is active routing authority.

## CURRENT RSK-01A.6 FRONTIER
The immediate technical edge remains:
`existing IABV MCP server capability + client configuration → live connected MCP session available to Codex`

However, this is a means to the broader laptop-native objective, not the product objective itself.

## DEVELOPER ROUTING RULE
For future prompts, first reconcile:
`overarching laptop-native objective + free-first constraint + current domain frontier + current verified truth`.
Then select the smallest capability-fit action.

Do not let a narrow audit frontier redefine the whole product objective.

## DEVELOPMENTAL INFLECTION CRITERION
Do not call the system 'exponential' because more capable agents can code faster.
The meaningful inflection is causal and cumulative:
`IABV state/memory → useful tool/AI selection → real execution in the laptop environment → verified observation → persistent reusable delta → later contextual retrieval → changed method/routing/decision`.

Once that loop is repeatedly demonstrated across different realizations (e.g. local app, browser, Codex, ChatGPT) with decreasing routine human coordination and preserved verification, an accumulating-development effect becomes an empirical question rather than only a design aspiration.

## STATUS
This record is a canonical objective/constraint reconciliation, not a claim that the full laptop-native loop or developmental inflection is already proven.
