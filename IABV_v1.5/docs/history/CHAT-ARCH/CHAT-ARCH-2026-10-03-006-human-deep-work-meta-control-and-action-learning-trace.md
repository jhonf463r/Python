The human asks that the project:
1. detect when actor routing or prompt generation is being inherited mechanically from the previous step;
2. treat the human's own deep-work reasoning as an explicit object of analysis rather than an invisible source of prompts;
3. test whether the protocol can expose, in human-visible form, why a decision was made, what was uncertain, what evidence supported it and what changed afterward;
4. compare this human-visible reasoning process with an operational super-metacognitive ideal;
5. progressively move routine context transport, evidence organization, actor selection and lesson extraction from the human toward IABV only when causality and governance are demonstrated;
6. preserve every material action as a traceable experience containing observation, verification, inference, lesson and reusable change;
7. use those traces to eventually test whether verified experience changes later selection and decision.

Working hypothesis:

deep-work control should improve on simple prompt chaining by explicitly checking objective, current truth, uncertainty, alternatives, evidence, capability-fit, action, verification, consequence and future reuse before selecting the next action.

Super-metacognition is retained only as an operational benchmark/hypothesis. It is not an established scientific construct.

## SUPER-METACOGNITIVE OPERATIONAL COMPARATOR

Use the following only as an experimental comparator:

1. Detect objective.
2. Reconstruct current verified state.
3. Identify uncertainty and hidden assumptions.
4. Separate facts, inferences, hypotheses and preferences.
5. Generate competing explanations.
6. Identify the smallest experiment that distinguishes them.
7. Select the actor/capability with best fit.
8. Predict what should be observed if the hypothesis is correct.
9. Execute only the minimum justified intervention.
10. Observe without silently converting observation into interpretation.
11. Independently verify the critical claim.
12. Reconcile contradictions.
13. Record what changed.
14. Convert only justified change into reusable knowledge.
15. Determine whether future routing/decision actually consumes that learned state.
16. If not, do not claim learning closure.

The comparator should be tested against both the user's actual reasoning process and the IABV protocol/process.

The objective is not to replace human judgment by assertion. The objective is to identify which routine cognitive coordination functions can eventually become machine-supported while preserving human control at governance, authorization, security and unresolved high-impact boundaries.

## AUTOMATION-BIAS / PROMPT-CHAINING EXPERIMENT

Observed methodological risk:

previous agent result → inherited next prompt → next agent result → inherited next prompt

can become a self-reinforcing chain even when every individual prompt appears reasonable.

This is a false-positive risk for symbiosis.

A valid cross-AI cycle should instead contain:

CURRENT OBJECTIVE → CURRENT VERIFIED TRUTH → FIRST OPEN EDGE → REQUIRED CAPABILITY → ACTOR FIT → ACTION → OBSERVATION → INDEPENDENT VERIFICATION → RECONCILIATION → KNOWLEDGE DELTA → ROUTING/METHOD CHANGE

and should explicitly record why the new next action was selected rather than merely inheriting the previous actor's recommendation.

## ACTION-TO-LEARNING TRACE

The durable unit for future developmental experiments is:

ACTION → OBSERVATION → VERIFICATION → FACT → INFERENCE → HYPOTHESIS / LESSON → KNOWLEDGE DELTA → CAPABILITY DELTA → ROUTING DELTA → NEGATIVE KNOWLEDGE → UNRESOLVED → FUTURE DECISION

Important distinctions:

report ≠ observation
observation ≠ inference
inference ≠ lesson
lesson ≠ verified reusable knowledge
knowledge update ≠ future decision change
future decision change ≠ improved outcome

A stronger learning claim requires the downstream edge to be demonstrated.

## USER-VISIBLE VS MACHINE-LEVEL TRACE

Maintain two related but distinct views.

### Human-visible view

The user should be able to understand:

what we are trying to solve → why this step → what happened → what was learned → what remains.

### Machine/provenance view

The system should eventually retain:

objective_id, episode_id, action_id, actor, capability, realization, resource, environment, authorization, input contract, expected result, observation, evidence source, verification, state-before, state-after, inference, lesson, knowledge delta, routing delta, provenance, freshness, contradiction status.

The existence of a machine-level record does not prove that it caused future behavior.
