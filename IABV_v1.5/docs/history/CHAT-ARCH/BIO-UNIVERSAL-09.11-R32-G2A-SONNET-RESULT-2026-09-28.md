## Key finding

The smallest existing production seam is:

`AppBootstrap(<isolated workspace>) → bootstrap.inference_service.infer_task(request)`

No call to `_build_ui_objects()` is required for the inference/lifecycle path.

`AppBootstrap.__init__(workspace_root, _defer_services=False)` calls `_wire_services()` by default.

Source reconciliation verifies that `_wire_services()` constructs and wires:

- persistence repositories and `ExperimentLab`;
- `AdaptiveWeightLayer` with an explicit workspace-derived `persistence_path`;
- `OllamaExpertProvider` as `general_provider`;
- `LocalRoleRouter(general_provider=...)`;
- `TaskOutcomeRecorder`;
- `AdaptiveTaskOrchestrator(task_outcome_recorder=...)`;
- `InferenceService(adaptive_orchestrator=...)`.

## Production call graph

`bootstrap.inference_service.infer_task()`
→ `InferenceService._execute()`
→ `AdaptiveTaskOrchestrator.handle_request()`
→ local-chat eligibility
→ `role_router.general_provider.health_check()`

Important runtime qualification:

`RunStatus.SUCCESS` alone does NOT prove Ollama executed.

The observable production indicator for real local-chat model participation is `result.raw_output['local_chat_llm']`, including provider/model/availability/error and related execution metadata.

## Recommendation lifecycle

A warm-up production execution can naturally generate an `ExperimentRecommendation` during `_record_learning()`.

The target execution then reads the prior recommendation through `latest_recommendation()` BEFORE creating the new outcome/recommendation.

The effective prediction confidence is the top-level:

`ExperimentRecommendation.confidence`

not `metadata['confidence']`.

The target should therefore observe the real recommendation generated by IABV rather than seed one.

## Isolation

The effective `AdaptiveWeightLayer` path is passed explicitly by AppBootstrap:

`<workspace>/data/evolution/adaptive_weights/metacognitive_adjustments.json`

The previous R32-G error was assigning `persistence_path` after construction. R32-G2 must avoid that pattern.

A new empty workspace passed to AppBootstrap is the correct isolation seam. Environment variables such as `IABV_WORKSPACE` remain relevant to other services, but AppBootstrap's explicit `workspace_root` controls the AdaptiveWeightLayer path.

## Runtime risks

- non-local-chat request can bypass the Ollama call while still yielding `RunStatus.SUCCESS`;
- Ollama server availability does not guarantee the configured model is loaded;
- production `general_provider` has a fixed 30-second timeout;
- bootstrap may trigger environment/world-model scans and related probes;
- `ToolCallingBridge` can participate in local-chat execution;
- warm-up and target must preserve the same subject/objective scope;
- domain and subject keys can vary through context-derived values, with `general` as a shared key.
