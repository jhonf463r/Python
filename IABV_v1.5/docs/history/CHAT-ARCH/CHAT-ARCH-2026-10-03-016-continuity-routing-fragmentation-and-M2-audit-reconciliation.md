# CHAT-ARCH-2026-10-03-016 — CONTINUITY / ROUTING FRAGMENTATION + BIO-04 M2 AUDIT RECONCILIATION

## PURPOSE

Record the independent M2 audit and, more importantly, reconcile a higher-order failure observed by the human: successive chats can activate different protocol/history entry paths and therefore lose previously learned/deduced state even when that state is already present in GitHub.

This is a methodological and routing reconciliation. It does not create a new runtime brain or a new permanent service.

## 1. CURRENT DIAGNOSIS

The repository contains a real continuity substrate, but continuity reliability is not equivalent to memory existence.

Observed structural hazard on main:
- 41 CHAT-ARCH records matched `Next actor:` in a repository search;
- 86 CHAT-ARCH records matched `CURRENT NEXT ACTOR:` in the search surface;
- 8 CHAT-ARCH files contain `ACTIVE OVERLAY`;
- 34 CHAT-ARCH files contain `READ THIS BEFORE`;
- multiple documents contain partially overlapping routing sequences, including README, MEMORY-OPERATING-PROTOCOL, AI-FRAME-ENTRY-PROTOCOL, Deep Research protocols, CURRENT-STATE, CONTEXT-INDEX and historical handoff records.

These counts are search-surface indicators, not counts of logically active routes. Their significance is that a retrieval system or new chat can encounter many plausible routing statements before it reconstructs the latest state.

Therefore the principal failure mode is:

`knowledge exists → retrieval activates one neighborhood → local protocol looks coherent → other material deltas are omitted → next route is locally correct but globally incomplete`.

This is different from:
`knowledge was never persisted`.

## 2. WHY THE EXISTING PROTOCOLS ARE NOT ENOUGH

The current protocols already contain strong anti-drift rules:
- current-state precedence over historical actor recommendations;
- objective-conditioned retrieval;
- dynamic capability-fit routing;
- negative-knowledge preservation;
- report-to-canonical-state conversion;
- concrete IA destination requirement.

However, these rules are distributed across multiple documents and dated addenda.

The system therefore has a protocol-of-protocols problem:

`one objective → many documents each describing part of how to choose the next document/actor`.

A semantic search hit can therefore select a protocol before it has selected the complete current frame.

The dangerous assumption is:

`retrieval of a relevant protocol = retrieval of the complete relevant state`.

That is NOT established.

## 3. R34 RECONCILIATION

R34 previously demonstrated blind reconstruction at a bounded level: a fresh Sonnet run could reconstruct important current objective/state/negative knowledge/routing information from GitHub without the original chat.

The new human observation does not refute that bounded result. It narrows its scope.

R34 status should be interpreted as:

`BLIND RECONSTRUCTION PROVEN FOR THE TESTED CASE`

but:

`GENERAL RELIABLE CROSS-CHAT ROUTING / RELEVANT-DELTAS RECALL = NOT PROVEN`.

Therefore a single successful blind reconstruction cannot be used as proof that arbitrary future chats will activate all material lessons and deductions.

## 4. SINGLE ROUTING SPINE — CANONICALIZATION RULE

The following division is now the intended control plane:

### README.md
Entry contract only. It tells a new participant what to read and what the precedence hierarchy is.

### CURRENT-STATE.md
**ONLY ACTIVE CURRENT ROUTING AUTHORITY.**
It must contain a compact top-level routing snapshot for the current active objective(s). Historical sections remain evidence/history and are not executable routing commands.

### CONTEXT-INDEX.md
Memory navigation and objective-conditioned retrieval map. It locates relevant records. It must not be treated as a competing current actor authority.

### MEMORY-OPERATING-PROTOCOL.md
Method and epistemic rules. It defines how to reason about routing, not which historical next actor is currently selected.

### SYMBIOSIS-MAP.md
Capability/knowledge/method/routing transfer evidence. It is not current routing authority.

### UNRESOLVED-KNOWLEDGE.md
Open questions, deductions, backlog and negative knowledge. It is not itself the active route.

### Historical records
Evidence-bearing source history. Any `NEXT ACTOR` inside them is historical unless explicitly re-promoted through CURRENT-STATE.

## 6. MATERIAL DELTA COMPRESSION RULE

No material cross-chat result should remain only in its source record.

Every material external-AI or human reasoning episode must either:
- produce a Knowledge/Method/Relation/Routing/Unresolved delta referenced from CURRENT-STATE and CONTEXT-INDEX; or
- be explicitly classified as non-material/no state change.

Therefore:

`historical detail → canonical delta → current routing snapshot`.

This reduces routine retrieval burden without deleting evidence.

## 7. PROTOCOL PROLIFERATION RULE

New protocol documents must not become new routing authorities.

A new protocol is justified only when it introduces a durable method/constraint that is not representable by an existing protocol.

Otherwise prefer:
`amend existing canonical protocol + add a dated source record`

over:
`create another top-level routing protocol`.

This directly addresses the observed tendency for each new chat to enter through a different conceptual doorway.

## 8. RETRIEVAL FAILURE MODES TO PRESERVE

### RF-1 — Protocol-first activation
The chat retrieves a protocol matching the topic and starts following it before current-state reconciliation.

### RF-2 — Historical next-actor capture
A search result exposes an old `NEXT ACTOR` and the model treats it as current despite precedence rules elsewhere.

### RF-3 — Domain-local memory
The chat retrieves M2 science but not the human-aware plasticity/routing lesson that changed how results should be handled.

### RF-4 — Method/state separation
The chat retrieves the method protocol but not the latest Knowledge/Method/Routing Delta produced by its recent use.

### RF-5 — Duplicate semantic surfaces
Multiple documents restate similar routing chains with slight differences, increasing selection variance.

### RF-6 — Current-state under-compression
Material deductions exist in historical records but are not summarized at the current routing layer.
