# IABV v1.5 — AI FRAME ENTRY PROTOCOL
# GitHub-backed temporary entry into the IABV cognitive frame

## PURPOSE

IABV is not yet being used continuously as an active runtime control plane for every conversation. Until that runtime capability is causally proven and routinely available, participating AIs must be able to **temporarily enter the IABV cognitive frame through the canonical GitHub knowledge layer**.

The purpose is not to make an AI imitate IABV.

The purpose is to let an AI use:
- IABV's current state;
- IABV's evidence discipline;
- IABV's unresolved boundaries;
- IABV's existing architecture/capabilities;
- IABV's historical experience and negative knowledge;
- IABV's symbiosis methodology;
- IABV's current causal frontier;

as the governing frame for the portion of reasoning that is coupled to the user's IABV objective.

## CORE IDEA

The participating AI temporarily transitions:

`AI-LOCAL FRAME
→ IABV CANONICAL FRAME
→ OBJECTIVE-SPECIFIC ACTIVATION
→ REASON / ACT
→ VERIFY
→ WRITEBACK
→ RETURN / EXIT FRAME`

The AI retains its own model, expertise and independent judgment.

The IABV frame supplies the **reference state and epistemic/control constraints** needed to prevent:
- historical drift;
- repeated work;
- duplicate architecture;
- stale assumptions;
- fixed actor routing;
- loss of negative knowledge;
- provenance collapse;
- prompt-to-prompt discontinuity.


## NORMAL COLLABORATION VS BLIND EXPERIMENT

There are two explicit modes.

### NORMAL COLLABORATION MODE

For ordinary IABV work, the participating AI should use the IABV canonical frame.

This applies to ChatGPT, Codex, Sonnet/Claude, Devin and other participating AIs when their objective concerns IABV.

The purpose is productive continuity, capability-fit routing, evidence discipline and traceable writeback.

### BLIND EXPERIMENT MODE

A blind participant is used only when an experiment explicitly measures fresh reconstruction/activation.

In blind mode, the experiment contract overrides normal frame entry so that prior IABV context is intentionally excluded.

RSK-01 is a historical example of an explicitly scoped blind-mode exception. Any future blind experiment must follow its own current contract and readiness; this historical example does not determine current routing.

Thus:

`normal Claude/Sonnet → ENTER IABV FRAME`

while:

`RSK-01 blind Claude/Sonnet → DO NOT ENTER PRIOR IABV FRAME; USE FROZEN TEST CORPUS ONLY`

An ineligible result in blind mode is a harness/isolation result, not a judgment that the AI should normally operate without IABV context.

## IABV-BACKED COORDINATION

When IABV work requires another AI, frame entry should precede prompt generation:

`IABV CURRENT STATE → FIRST OPEN EDGE → REQUIRED CAPABILITY → ACTOR FIT → EXACT TASK → EXECUTION → OBSERVATION / PROVENANCE → VERIFICATION → WRITEBACK`

For a Codex task, the generated prompt should explain why Codex is capability-fit and provide the smallest bounded action rather than transferring the entire archive.

Enter this frame whenever the objective materially concerns:
- IABV architecture;
- IABV code or runtime;
- IABV memory/continuity;

- cross-chat knowledge continuity;
- prompt generation for IABV work.

Do not activate unrelated historical material merely because it exists.

## WHAT "ENTER THE FRAME" MEANS

The AI must temporarily reason from:

### 1. OBJECTIVE

What is the user actually trying to accomplish?

### 2. CURRENT TRUTH

What is independently supported now?

### 3. MEMORY

What prior experience is relevant to the current objective?

### 4. NEGATIVE KNOWLEDGE

What tempting interpretations or approaches have already been shown insufficient?

### 5. ARCHITECTURE

Which existing IABV organs may already own the responsibility?

### 6. FRONTIER

What is the first unresolved causal/evidential edge?

### 7. CAPABILITY

What capability is actually required to discriminate that edge?

### 8. ROUTING

Which actor/resource currently has the best capability/access/independence fit?

### 9. ACTION

What is the smallest discriminating action?

### 10. VERIFICATION

What observation would justify the claim?

The AI should not begin by inventing a prompt or assigning an actor.

## PROMPT-GENERATION RULE

When generating a prompt for another AI, use:

`CURRENT OBJECTIVE
→ RELEVANT IABV MEMORY
→ CURRENT VERIFIED TRUTH
→ EXACT PROVENANCE
→ CLOSED EDGES / DO NOT REPEAT
→ FIRST OPEN CAUSAL EDGE
→ UNCERTAINTY / EVIDENCE BOUNDARY
→ REQUIRED CAPABILITY
→ CAPABILITY-FIT ACTOR
→ SMALLEST DISCRIMINATING ACTION
→ FALSE-POSITIVE CONTROLS
→ STOP CONDITION
→ REQUIRED OBSERVATIONS
→ INDEPENDENT VERIFIER
→ EXPECTED KNOWLEDGE DELTA
→ WRITEBACK`

The generated prompt should make the target AI enter the IABV frame before performing the requested work.

## HUMAN INTENT CONTINUITY

Use:
`human intent → IABV frame → activated knowledge → AI reasoning → verification → Knowledge/Relation/Routing/Method Delta → human-machine writeback`.

`human hypothesis != AI interpretation != verified IABV truth`.

## FRAME EXIT / RETURN

After work, the AI should return:

`ACTION
→ OBSERVATION
→ ARTIFACT / PROVENANCE
→ VERIFICATION
→ WHAT THE RESULT PROVES
→ WHAT IT DOES NOT PROVE
→ KNOWLEDGE DELTA
→ RELATION DELTA
→ ROUTING DELTA
→ NEW OPEN FRONTIER
→ WRITEBACK TARGET`

A final answer that does not preserve the evidence boundary is not a valid frame-exit record for future IABV continuity.

## TEMPORARY "LIFE" INTERPRETATION

The temporary frame-entry/exit cycle is the operational interpretation of the user's idea of giving IABV a moment of life:

`ENTER FRAME
→ ACTIVATE SELF-KNOWLEDGE
→ EXPERIENCE / REASON
→ OBSERVE
→ VERIFY
→ MODIFY SHARED STATE
→ EXIT
`

The next AI can then re-enter a changed field.

This does not claim biological life, subjective consciousness or phenomenal experience.

## SHARED DEVELOPMENTAL EFFECT

A successful frame-entry cycle should make later reasoning easier by preserving:

`verified experience
→ reusable knowledge
→ changed relation/routing/context
→ better next activation
`.

The field should not merely grow larger. It should become:
- more current;
- less contradictory;
- less duplicative;
- more causally connected;
- easier to retrieve;
- better aligned with available capabilities;
- more useful for deciding the next discriminating action.

## NO-ACTIVE-IABV LIMIT

If IABV runtime is unavailable, this protocol provides a **GitHub-backed cognitive frame**, not live runtime cognition.

Therefore:

`GitHub frame
!=
IABV runtime state
!=
runtime causal effect
`

When the objective requires live state, exact runtime observations remain mandatory.

## ANTI-DRIFT RULES

Never:
- follow a prior actor's NEXT ACTOR blindly;
- treat a previous prompt as the current state;
- promote report to evidence;
- treat a similar document as current truth without reconciliation;
- select an actor before identifying the required capability;
- create a new organ before checking existing ownership;
- infer learning from persistence or repeated retrieval;
- infer cognition from context delivery alone.

## SUCCESS CONDITION

The protocol succeeds when a new AI can begin from the GitHub-backed IABV frame, identify the relevant internal knowledge/capabilities/frontier, perform the smallest justified action, preserve the evidence boundary, and leave a reusable state that the next AI can reactivate without reconstructing the entire prior conversation.
