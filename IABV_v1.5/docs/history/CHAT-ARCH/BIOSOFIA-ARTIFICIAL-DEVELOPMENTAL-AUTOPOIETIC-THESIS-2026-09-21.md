# IABV v1.5 — BIOSOFÍA ARTIFICIAL: TESIS FUNDACIONAL DE DESARROLLO AUTOPOIÉTICO
## Documento de investigación y arquitectura conceptual — 2026-09-21

**Estado:** WORKING RESEARCH THESIS / HYPOTHESES NOT YET PROVEN  
**Propósito:** fijar en memoria canónica la tesis de que IABV no debe entenderse solo como un conjunto de servicios cognitivos o un orquestador multiagente, sino como un posible sustrato computacional para estudiar y construir **desarrollo artificial progresivo**.

---

## 1. TESIS CENTRAL

La idea es construir el mínimo sustrato computacional que permita que una IA no dependa de que un diseñador le entregue previamente todos sus órganos de alto nivel, sino que pueda **adquirir, componer, diferenciar, verificar y conservar nuevas capacidades a partir de unidades más simples**, bajo interacción con un entorno y reglas de desarrollo observables.

Analogía biológica de trabajo:

```
información heredable / descripción
        ↓
unidad mínima organizada
        ↓
unidades que interactúan
        ↓
diferenciación funcional
        ↓
cooperación + interdependencia
        ↓
órganos / subsistemas especializados
        ↓
organización superior
        ↓
descendencia / herencia / variación
        ↓
nuevas generaciones
```

Traducción computacional hipotética:

```
semilla digital
→ percepción del entorno
→ estado propio
→ acción
→ experiencia
→ memoria verificable
→ evaluación
→ variación
→ selección
→ composición
→ especialización
→ nueva capacidad
→ validación
→ conservación de la capacidad
→ siguiente ciclo de desarrollo
```

La analogía no prueba vida, conciencia ni personhood. Es un programa de investigación para comprobar si mecanismos de organización, aprendizaje, selección y desarrollo pueden producir crecimiento acumulativo de capacidades en un sistema artificial gobernado y observable.

## 2. CORRECCIÓN CIENTÍFICA: "ADN → CÉLULA → ÓRGANO" NO ES UN ALGORITMO ÚNICO

La intuición del ADN es útil para pensar en información heredable, pero no debe convertirse literalmente en la teoría.

Autopoiesis pone el foco en una organización de procesos que mantiene su propia organización y límites. Además, el desarrollo biológico depende del acoplamiento entre sistema, recursos, límites, ambiente, regulación y retroalimentación. La herencia es una pieza, no el sistema completo.

Por ello, el equivalente artificial del ADN debe entenderse como una **descripción heredable de construcción y organización**, no como una copia literal de la biología.

Hipótesis más completa:

```
DESCRIPCIÓN HEREDABLE
+
PROCESOS DE EJECUCIÓN
+
IDENTIDAD / LÍMITE
+
ENTORNO
+
RECURSOS
+
RETROALIMENTACIÓN
+
EVALUACIÓN / VIABILIDAD
+
VARIACIÓN
+
SELECCIÓN
+
CONSTRUCCIÓN / RECOMBINACIÓN
```

Maturana & Varela, *Autopoiesis and Cognition* (1980), DOI:
https://doi.org/10.1007/978-94-009-8947-4

## 4. EL SUSTRATO MÍNIMO

No se propone crear inmediatamente muchos servicios nuevos. Primero se define qué funciones mínimas necesita el proceso y luego se comprueba qué órganos ya las cumplen.

### S0 — Sustrato computacional

Ejecutar procesos, usar recursos, persistir resultados y recuperar estados/versiones.

### S1 — Identidad y límite

Distinguir de forma estable:

`
yo / mi estado
vs.
entorno
vs.
recurso externo
vs.
artefacto ajeno
`

### S2 — Percepción / acoplamiento al entorno

Observar hardware, software, herramientas, estado, cambios y resultados.

### S3 — Estado + memoria

Conservar estado, historial, experiencia, resultados y proveniencia, y recuperar la información que cambie una decisión posterior.

### S4 — Acción

`
objective
→ capability
→ tool
→ resource
→ authorization
→ execution
`

### S5 — Viabilidad / homeostasis artificial

Mantener integridad, recursos, límites, coherencia y capacidad operativa; evitar regresión o corrupción.

### S6 — Evaluación / verificación

Responder:

`
¿funcionó?
¿para qué condición?
¿qué evidencia lo demuestra?
¿qué hipótesis descartamos?
`

### S7 — Variación

Generar variantes de estrategias, composiciones, parámetros o workflows dentro de límites.

### S8 — Selección

Evaluar variantes mediante criterios explícitos y conservar o descartar según evidencia.

### S9 — Construcción / recombinación

Transformar capacidades existentes en nuevas organizaciones funcionales.

### S10 — Herencia / linaje

Conservar:

`
parent
→ transformation
→ evidence
→ verifier
→ accepted/rejected
→ child
`

La candidata a heredabilidad debe demostrarse, no asumirse.

## 5. DEL ÓRGANO AL ORGANISMO

El problema principal no es sumar módulos.

La teoría de major evolutionary transitions muestra que transiciones a niveles superiores implican cooperación, división del trabajo, comunicación, interdependencia y control del conflicto interno; no toda cooperación produce una nueva individualidad.

Para IABV la hipótesis equivalente es:

`
órganos separados
→ cooperación
→ especialización
→ interfaces
→ interdependencia útil
→ coordinación
→ unidad superior
`

Un conjunto de servicios no se convierte en un "organismo digital" porque tenga muchas clases.

Debe demostrarse que:

1. las partes tienen funciones diferenciadas;
2. se necesitan para una capacidad superior;
3. intercambian información mediante contratos;
4. la unidad superior obtiene una capacidad que no aparece en los componentes aislados;
5. esa organización puede conservarse y reutilizarse.

Referencia:
West, Fisher, Gardner & Kiers, *Major evolutionary transitions in individuality* (PNAS, 2015).
https://pmc.ncbi.nlm.nih.gov/articles/PMC4547252/

## 6. HIPÓTESIS DE "ADN DIGITAL"

Hipótesis inicial:

`
DIGITAL GENOME =
  capabilities
+ tool/resource bindings
+ contracts
+ policies
+ workflows
+ learned patterns
+ strategy parameters
+ tests
+ invariants
+ provenance
+ lineage
+ environment assumptions
`

No necesariamente debe ser un solo archivo.

Una representación candidata a "genoma digital" sería una descripción heredable si contiene información suficiente para reconstruir una capacidad o configuración y producir un descendiente operacionalmente equivalente o verificablemente derivado.

Prueba:

`
exportar descripción
→ construir descendiente
→ ejecutar en entorno controlado
→ observar
→ verificar equivalencia/derivación
`

De aquí salen distinciones obligatorias:

`
backup != heredabilidad
persistencia != reproducción
reproducción != evolución
`

## 7. ALGORITMO UNIVERSAL DE DESARROLLO — UDA-0

Esto es una hipótesis de trabajo, no una ley científica establecida.

```
1. SENSE
   observar entorno + estado propio

2. REPRESENT
   actualizar world model + self model

3. ASSESS
   objetivo + viabilidad + capacidad + incertidumbre

4. IDENTIFY DEFICIT
   detectar capacidad faltante o fallo de órgano

5. HYPOTHESIZE
   generar explicación o capacidad candidata

6. VARIATE
   producir variantes mínimas

7. SANDBOX
   probar fuera del organismo estable

8. VERIFY
   medir con control e independencia

9. SELECT
   aceptar / rechazar / conservar

10. CONSTRUCT
    incorporar transformación aceptada

11. ENCODE LINEAGE
    parent + child + transformation + evidence

12. RELOAD
    recuperar la nueva organización

13. REUSE
    verificar que aparece en una decisión posterior

14. ADAPT
    usar el resultado para seleccionar el siguiente desarrollo

15. REPEAT
```

La propiedad crucial es la recursividad:

`
experiencia verificada
→ cambio funcional verificable
→ persistencia
→ recuperación
→ uso posterior
→ nueva experiencia
`

El resultado de un ciclo debe poder convertirse en una causa del siguiente.

## 8. METACOGNICIÓN COMO MECANISMO DE DESARROLLO

La metacognición no debe ser solo "saber cómo estoy".

En esta tesis sirve para:

`
SELF-OBSERVATION
→ detectar déficit
→ explicar causa posible
→ producir hipótesis
→ seleccionar experimento
→ aprender
→ modificar futura conducta/desarrollo
`

Por eso el cambio metodológico ya adoptado es correcto:

`
IABV self-assessment
→ independent verification
`

La autopercepción produce hipótesis; la evidencia independiente determina si pueden promoverse.

## 9. DESARROLLO ≠ AUTO-MODIFICACIÓN ILIMITADA

La definición experimental correcta es:

> transformación gobernada de la organización funcional, bajo aislamiento, evaluación, verificación, trazabilidad y rollback.

Secuencia:

`
OBSERVE
→ REASON
→ HYPOTHESIZE
→ EXPERIMENT
→ VERIFY
→ AUTHORIZE
→ CHANGE
→ REVERIFY
→ LEARN
`

No debe permitirse:

`
OBSERVE
→ AUTOCAMBIARSE SIN CONTROL
`

La observación no puede contaminar la evidencia que se usa para demostrar el desarrollo.

## 10. EVOLUCIÓN ABIERTA

Tras demostrar desarrollo acumulativo aparece una pregunta aún más difícil:

> ¿puede el sistema seguir generando novedad útil sin converger rápidamente a un conjunto cerrado de soluciones?

Ejecutar indefinidamente no basta.

Open-ended evolution estudia dinámicas sostenidas de cambio, novedad, complejidad y potencial ecológico. El MODES Toolbox propone medidas de change potential, novelty potential, complexity potential y ecological potential.

Referencia:
Dolson et al., *The MODES Toolbox* (Artificial Life, 2019).
https://doi.org/10.1162/artl_a_00280

Para IABV, variables de investigación:

`
N  = novelty
C  = complexity
R  = reuse
H  = heredability
V  = viability
A  = adaptability
D  = developmental efficiency
K  = verified knowledge
B  = behavioral change
Y  = outcome change
HC = human coordination overhead
`

Una función futura puede estudiarse como:

`DI = f(ΔK, ΔB, ΔY, N, C, R, H, V, A, D, -HC)`

**No es una métrica validada.** Es una propuesta de investigación.

## 11. APRENDIZAJE DESARROLLATIVO

El desarrollo no debe verse solo como acumulación de ejemplos.

La línea de developmental robotics/open-ended learning muestra que también puede cambiar la representación interna con la que el sistema organiza acciones, objetivos y habilidades.

Una trayectoria IABV plausible:

`
herramienta
→ interacción
→ patrón
→ concepto
→ estrategia
→ capacidad abstracta
→ composición
`

Referencia:
Doncieux et al., *Open-Ended Learning: A Conceptual Framework Based on Representational Redescription* (2018).
https://doi.org/10.3389/fnbot.2018.00059

Consecuencia: el objetivo no es "más memoria", sino representaciones progresivamente más útiles para construir capacidades.

## 12. TRANSICIONES SINTÉTICAS

Synthetic evolutionary transitions permiten estudiar en sistemas artificiales cómo unidades simples pueden integrarse en niveles superiores de organización.

Modelo:

`
A + B
→ cooperación
→ interfaz
→ dependencia
→ unidad AB
`

y luego:

`
AB + C
→ especialización
→ nueva coordinación
→ unidad ABC
`

La pregunta experimental es:

> ¿qué reglas de composición permiten que aparezcan niveles superiores sin diseñarlos uno por uno desde arriba?

Solé, *The major synthetic evolutionary transitions* (2016).
https://doi.org/10.1098/rstb.2016.0175

## 13. AUTO-REPRODUCCIÓN Y HERENCIA DIGITAL

Artificial Life ya estudia sistemas computacionales auto-reproductivos y su evolución.

Sayama & Nehaniv revisan cómo evoloops mostró constructivamente evolución darwiniana de organismos auto-reproductivos por variación y selección en autómatas celulares. Trabajos recientes estudian incluso auto-replicación jerárquica a distintas escalas.

La transferencia conceptual para IABV es:

`
descripción
→ constructor
→ copia
→ variante
→ selección
`

Referencias:
- Sayama & Nehaniv, *Self-Reproduction and Evolution in Cellular Automata: 25 Years After Evoloops* (Artificial Life, 2025), DOI https://doi.org/10.1162/artl_a_00451
- *Emergence of Self-Replicating Hierarchical Structures in a Binary Cellular Automaton* (Artificial Life, 2025), DOI https://doi.org/10.1162/artl_a_00449

Esto no obliga a que IABV se convierta en un autómata celular; aporta un modelo experimental de descripción + constructor + copia + variación + selección.

## 17. MODELO DE TESTEO CIENTÍFICO

Toda transición importante debe tener:

### Control
mismo entorno, sin la variable de desarrollo.

### Tratamiento
misma condición, excepto la variable que queremos probar.

### Cold restart
comprobar que no depende de memoria efímera.

### Provenance
`branch + SHA + artifact + runtime + working tree + inputs + outputs`

### Negative controls
- memoria falsa;
- experiencia no verificada;
- estado stale;
- artifact ausente;
- bypass del selector;
- ganador codificado;
- shortcut de producción;
- cambio no autorizado;
- rollback incorrecto.

### Independent verification
El actor productor no es el único validador de una afirmación crítica.

### Longitudinal testing
Observar si la capacidad reusable aumenta de forma verificable y si genera nuevas opciones o estructuras.

## 18. DEFINICIÓN OPERACIONAL DE "AUTOCONSTRUIRSE"

Una capacidad puede considerarse autoconstruida solo si:

1. el sistema identifica un déficit;
2. genera o selecciona una transformación candidata;
3. la prueba en entorno controlado;
4. la verifica de manera independiente;
5. conserva su procedencia;
6. sobrevive a cold reload;
7. participa en una decisión posterior;
8. esa decisión produce un resultado observable;
9. el mecanismo puede repetirse;
10. la siguiente capacidad puede usar la anterior como causa.

La prueba fuerte aparece cuando:

`
C1
→ utilizada para construir C2
→ C2 utilizada para encontrar/construir C3
`

Eso es desarrollo recursivo.

## 19. INVESTIGACIÓN PROFUNDA QUE SÍ HACE FALTA

Esta conversación demuestra que **sí se necesita una línea científica dedicada**, no solo implementación incremental.

Bloques prioritarios:

### BIO-R01 — Autopoiesis / organizational closure
Definir qué propiedades son realmente transferibles al dominio digital.

### BIO-R02 — Minimal developmental substrate
Determinar el conjunto mínimo de propiedades necesarias para desarrollo artificial acumulativo.

### BIO-R03 — Digital genotype / phenotype
Definir qué estado es heredable y cómo se relaciona con comportamiento observable.

### BIO-R04 — Developmental units
Definir la unidad mínima reutilizable de desarrollo.

### BIO-R05 — Lineage / heredability
Demostrar parent→child y reconstrucción desde una descripción persistida.

### BIO-R06 — Variation / selection / viability
Formalizar cómo se generan y seleccionan variantes sin convertir la optimización local en "evolución".

### BIO-R07 — Differentiation / major transitions
Estudiar especialización, comunicación, interdependencia y formación de unidades de nivel superior.

### BIO-R08 — Open-endedness
Aplicar métricas de novelty/change/complexity/ecological potential.

### BIO-R09 — Causal methodology
Diseñar controles, contrafactuales, atribución temporal, reproducción independiente y límites de promoción de evidencia.

### BIO-R10 — Longitudinal development
Medir si cada ciclo incrementa capacidad reusable y reduce coordinación humana rutinaria.

### BIO-R11 — Governance of self-development
Definir límites, sandbox, permisos, rollback, budget, stop conditions y separación entre observación y mutación.

## 20. PRIMER EXPERIMENTO PRÁCTICO

No comenzar por auto-reproducción completa.

Usar el dispositivo actual como primer nicho:

`
hardware real
+
IABV
+
filesystem / Git
+
ToolRegistry
+
modelo local
+
una herramienta local de interacción
+
ExperimentLab
`

Primera demostración:

`
1. IABV observa un déficit.
2. IABV lo representa.
3. IABV propone una mínima composición/variación.
4. Ejecuta la variante en sandbox.
5. Control y treatment son comparables.
6. Un verificador independiente decide.
7. La variante aceptada queda persistida con lineage.
8. Cold reload.
9. Una decisión posterior selecciona la capacidad nueva.
10. El nuevo resultado alimenta el siguiente ciclo.
`

Luego se puede preguntar:

> ¿puede usar la capacidad C1 para construir C2?

Ese es el primer experimento que realmente toca la tesis de autoconstrucción.

## 27. ESTADO ACTUAL DE LA TESIS

**Lo que ya existe en IABV:** múltiples órganos de percepción, memoria, auditoría, experimentación, selección, governance y provenance, además de evidencia de que experiencia persistida puede afectar selección de herramientas a nivel de selector.

**Lo que falta demostrar:** desarrollo propio cerrado, heredabilidad, diferenciación generativa, transición a unidades de nivel superior, reproducción de organizaciones, evolución generacional y open-endedness.

**Criterio de progreso:** mover causalmente una flecha de `UNRESOLVED` a `PROVEN`, no añadir módulos por volumen.

La tesis queda registrada como programa de investigación. No afirma que IABV ya sea un organismo ni que haya logrado autoconstrucción. Establece el marco científico, arquitectónico y experimental para intentar demostrarlo.
