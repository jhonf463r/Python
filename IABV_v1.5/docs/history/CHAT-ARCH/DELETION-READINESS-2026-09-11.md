# IABV v1.5 — Historical Chat Deletion Readiness — 2026-09-11

## PURPOSE

This is the deletion-readiness adjudication derived from direct GitHub inspection of historical chat archives and the canonical operational-memory layer.

Deletion safety is a **knowledge-preservation property**, not a technical-task-closure property.

## GATE

A chat is project-continuity deletion-safe when:

`DIRECT_CANONICAL_SOURCE=YES`
OR
`CANONICAL_KNOWLEDGE_ABSORPTION=YES`

AND:

`PROVENANCE_TO_SOURCE=YES`
`REMOTE_READBACK=YES`
`KNOWLEDGE_LOSS_TEST=PASS`
`BLIND_RECONSTRUCTION=PASS`
`NO_MATERIAL_KNOWLEDGE_ONLY_IN_CHAT=YES`

An open engineering objective does not automatically fail the gate.

## BLIND RECONSTRUCTION METHOD

The reconstruction is performed from canonical GitHub memory without using the old chat as an input during reconstruction. A reconstructed record must recover the material problem, major discoveries, false positives, evidence limits, decisions, pending work, cross-IA learning and next uncertainty that would materially affect future project decisions.

The criterion is not verbatim transcript reproduction.
