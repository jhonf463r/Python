# P0.213 Architecture Correction Plan

**Date:** August 19, 2026  
**Objective:** Design minimal trusted execution identity boundary for IABV v1.5  
**Scope:** Architectural correction for P0.213 security boundary gap  
**Status:** Design phase - NO implementation

---

## A. Executive Summary

**Problem:** IABV v1.5 possesses execution identifiers (RunRecord.run_id, AdaptiveSession.session_id) but lacks a trusted authority that can demonstrate these identifiers correspond to the actual process/execution.

**Root Cause:** The trust chain is broken at the first step - there is no trusted process identity authority. All downstream components rely on fabricable IDs generated by callers.

**Impact:** P0.213 implementation (PR #446) received P0_213_CODEX_FAIL from Codex audit due to fabricable identity, insufficient IPC validation, and missing stale-lease invalidation.

**Solution:** Implement minimal trusted runtime authority that provides non-fabricable process identity and canonical execution identity, integrated with existing runtime bootstrap without creating unnecessary new authorities.

**Approach:** Extend existing runtime bootstrap with a lightweight identity authority that leverages Windows process identity and named pipe security to establish trust anchors.

---

## B. Root Cause

### Current Broken Trust Chain
```
REAL RUNTIME
    ↓
[MISSING] - No trusted process identity authority
    ↓
[FABRICABLE] - RunRecord.run_id (uuid4 generated by caller)
    ↓
[FABRICABLE] - AdaptiveSession.session_id (uuid4 generated by caller)
    ↓
[FABRICABLE] - CanonicalExecutionIdentity (derived from fabricable IDs)
    ↓
[WEAK] - InternalMcpInvocation (weak validation)
    ↓
[WEAK] - IPC (no DACL, PID validation at app level only)
    ↓
[NO VALIDATION] - SelfAudit (does not validate identity)
    ↓
[NO VALIDATION] - Learning (assumes IDs are legitimate)
```

### Fundamental Gap
**MISSING_CANONICAL_AUTHORITY** - No trusted runtime authority exists that can provide non-fabricable process identity and canonical execution identity.

## C. Trust Anchors

### Windows Process Identity
**Classification:** **TRUSTED**

**Capabilities:**
- Actual PID cannot be spoofed by caller
- Parent PID can be obtained via Windows API
- Process start timestamp is OS-controlled
- Process handle/token provides OS-level identity
- Named pipe client PID can be obtained via Windows API

**Limitations:**
- PID can be reused after process termination
- No direct cryptographic binding to process
- Requires Windows API calls (GetNamedPipeClientProcessId)

### Windows Named Pipe DACL/ACL
**Classification:** **TRUSTED**

**Capabilities:**
- Can restrict pipe access to specific process SID
- Can enforce parent-child relationship via security descriptor
- OS-level enforcement, not application-level
- Prevents unauthorized process connection

**Limitations:**
- Requires Windows security API
- Complex to configure correctly
- May require process elevation for certain operations

### Process Creation Event
**Classification:** **PARTIALLY_TRUSTED**

**Capabilities:**
- Process creation timestamp is OS-controlled
- Parent process identity is OS-controlled
- Launcher-owned process relationship can be established

**Limitations:**
- Requires monitoring process creation events
- May require Windows API hooks
- Not directly accessible from Python without extensions

### Runtime Bootstrap State
**Classification:** **PARTIALLY_TRUSTED**

**Capabilities:**
- Bootstrap timestamp is controlled by runtime
- Bootstrap configuration is runtime-controlled
- Can establish runtime incarnation identity

**Limitations:**
- Can be restarted/recreated
- No cryptographic binding to process
- Requires persistence for cross-session validation

### Existing Main Process Identity
**Classification:** **PARTIALLY_TRUSTED**

**Capabilities:**
- Main process PID is OS-controlled
- Main process start timestamp is OS-controlled
- Can serve as trust anchor for child processes

**Limitations:**
- Can be restarted
- No cryptographic binding
- Requires child process to validate parent identity

### Existing MCP Child Identity
**Classification:** **UNTRUSTED**

**Capabilities:**
- Child process PID is OS-controlled
- Child process start timestamp is OS-controlled

**Limitations:**
- Child process can be fabricated
- No validation of parent-child relationship
- No cryptographic binding to parent

### Caller-Generated UUID
**Classification:** **UNTRUSTED**

**Capabilities:**
- None - completely fabricable

**Limitations:**
- Any caller can generate arbitrary UUID
- No binding to process or execution
- No provenance verification possible

## D. Process Identity

### How to Prove PID Belongs to Actual Process

**Windows Named Pipe Capabilities:**
- `GetNamedPipeClientProcessId()` - Returns actual client PID
- `GetNamedPipeServerProcessId()` - Returns actual server PID
- Can be called after pipe connection is established
- OS-level validation, not caller-provided

**Implementation Strategy:**
1. Server creates named pipe with restricted DACL
2. Client connects to pipe
3. Server calls `GetNamedPipeClientProcessId()` to obtain actual client PID
4. Server validates client PID against expected parent/child relationship
5. Server validates client process start timestamp
6. Server issues capability only if validation succeeds

**Parent PID Validation:**
- Use `CreateToolhelp32Snapshot()` + `Process32First()` + `Process32Next()` to enumerate processes
- Use `OpenProcess()` to obtain process handle
- Use `GetProcessTimes()` to obtain process creation time
- Validate parent-child relationship via process tree

**Process Lineage Validation:**
- Build process tree from parent PIDs
- Validate that child process is descendant of expected parent
- Validate process creation timestamps are consistent
- Reject if lineage is inconsistent

## E. IPC Trust Boundary

### Required Architecture

```
IABV Parent Process
    ↓
[Create Named Pipe with DACL]
    ↓
[Wait for Connection]
    ↓
MCP Child Process
    ↓
[Connect to Named Pipe]
    ↓
[Server: GetNamedPipeClientProcessId()]
    ↓
[Server: Validate Client PID]
    ↓
[Server: Validate Parent-Child Relationship]
    ↓
[Server: Issue Capability]
    ↓
[Transport Identity Established]
    ↓
[Application Identity Validated]
```

### Transport Identity vs Application Identity

**Transport Identity:**
- OS-level process identity (PID, process handle)
- Validated via Windows API
- Cannot be spoofed by caller
- Established at pipe connection time

**Application Identity:**
- Canonical execution identity (run_id, session_id)
- Validated via runtime authority
- Derived from trusted process identity
- Established after transport identity is validated

**Relationship:**
- Transport identity is prerequisite for application identity
- Application identity cannot be established without validated transport identity
- Separation of concerns: OS handles transport, runtime handles application

### DACL/ACL Requirement

**Classification:** **MANDATORY**

**Rationale:**
- Defense-in-depth: OS-level enforcement prevents unauthorized connection
- Application-level validation is insufficient (can be bypassed)
- DACL provides first line of defense before application logic runs
- Prevents same-user malicious process from connecting to pipe

**Threat Addressed:**
- Unauthorized pipe access
- Same-user malicious process
- Wrong child process

**Implementation:**
- Create security descriptor with specific SID for parent process
- Grant only necessary permissions (read/write)
- Deny all other processes
- Use `SetSecurityInfo()` to apply security descriptor to pipe

## F. Runtime Incarnation / Generation

### Can It Be Derived from Existing Canonical Combination?

**Analysis:**

**Process Start Timestamp:**
- Available via `GetProcessTimes()`
- OS-controlled, cannot be spoofed
- Can serve as incarnation identifier
- **LIMITATION:** Process can be restarted with same timestamp (unlikely but possible)

**Boot/Session Identity:**
- Windows session ID is available via `WTSGetActiveConsoleSessionId()`
- OS-controlled, cannot be spoofed
- Can serve as session identifier
- **LIMITATION:** Session can persist across process restarts

**Launcher Instance:**
- Launcher process PID is OS-controlled
- Launcher process start timestamp is OS-controlled
- Can serve as launcher identity
- **LIMITATION:** Launcher can be restarted

**Runtime Bootstrap Identity:**
- Bootstrap timestamp is runtime-controlled
- Bootstrap configuration is runtime-controlled
- Can serve as bootstrap identity
- **LIMITATION:** Bootstrap can be restarted

**Persisted Runtime State:**
- Existing persisted state can serve as incarnation identifier
- Can be incremented on each runtime restart
- **LIMITATION:** Requires persistence and atomic increment

### Recommended Approach: Hybrid Derivation

**Runtime Incarnation = f(process_start_timestamp, bootstrap_timestamp, persisted_generation)**

**Components:**
1. **Process Start Timestamp** - OS-controlled, provides base identity
2. **Bootstrap Timestamp** - Runtime-controlled, provides runtime identity
3. **Persisted Generation** - Incremented on each restart, provides restart identity

**Derivation:**
```python
runtime_incarnation = hash(
    process_start_timestamp,
    bootstrap_timestamp,
    persisted_generation
)
```

**Lifecycle:**
- Created at runtime bootstrap
- Persisted in runtime state file
- Incremented on each runtime restart
- Used to invalidate stale leases

**Restart Semantics:**
- On restart: increment persisted_generation
- New incarnation ≠ old incarnation
- Old leases with old incarnation are invalid
- New leases with new incarnation are valid

**Comparison:**
- Incarnations are compared by hash
- Different incarnations = different runtime instances
- Same incarnation = same runtime instance

**Stale Invalidation:**
- Lease contains incarnation at issuance time
- On lease consumption: compare lease incarnation with current incarnation
- If different: lease is stale, reject consumption
- If same: lease is valid, allow consumption

## G. Canonical Execution Identity

### Redesigned Contract

**Who Can Create It?**
- **ONLY:** Trusted runtime authority (RuntimeIdentityAuthority)
- **NOT:** Caller
- **NOT:** Application logic
- **NOT:** External process

**Who Can Obtain It?**
- **ONLY:** Components that receive it from RuntimeIdentityAuthority
- **NOT:** Caller construction
- **NOT:** Direct instantiation

**Who Can Transport It?**
- **ANY:** Components can transport it (it's a data model)
- **BUT:** Transport does NOT imply authority
- **Authority is in the issuance, not the transport**

**Who Can Validate It?**
- **ONLY:** RuntimeIdentityAuthority
- **NOT:** Application logic
- **NOT:** External process

**Can a Caller Construct It?**
- **NO:** Constructor is private or factory method is internal
- **NO:** Direct instantiation is prevented
- **ONLY:** RuntimeIdentityAuthority can create instances

**Can It Be Serialized?**
- **YES:** For transport via IPC
- **BUT:** Serialization does NOT imply authority
- **Authority is validated at deserialization time

**How Is Its Provenance Verified?**
- **Cryptographic binding:** Contains HMAC signed by RuntimeIdentityAuthority
- **Process binding:** Contains process PID and incarnation
- **Timestamp binding:** Contains issuance timestamp
- **Validation:** RuntimeIdentityAuthority validates HMAC, process binding, timestamp

**What Links It to the Real Process?**
- **Process PID:** Obtained from OS via `GetNamedPipeClientProcessId()`
- **Process start timestamp:** Obtained from OS via `GetProcessTimes()`
- **Runtime incarnation:** Derived from process start + bootstrap + persisted generation
- **Cryptographic signature:** HMAC signed by RuntimeIdentityAuthority with secret key

### Redesigned Structure

```python
@dataclass(frozen=True)
class CanonicalExecutionIdentity:
    """Canonical execution identity issued by trusted runtime authority.
    
    This identity is NOT fabricable by callers. It can ONLY be created
    by RuntimeIdentityAuthority and is cryptographically bound to the
    actual process and runtime incarnation.
    """
    # Identity fields
    run_id: str  # UUID, but issued by authority, not caller
    episode_id: str | None
    session_id: str  # UUID, but issued by authority, not caller
    invocation_id: str  # UUID, but issued by authority, not caller
    
    # Process binding
    process_pid: int  # Actual process PID from OS
    process_start_timestamp: float  # Process creation time from OS
    
    # Runtime binding
    runtime_incarnation: str  # Hash of process start + bootstrap + generation
    
    # Issuance metadata
    issued_at_utc: datetime
    expires_at_utc: datetime | None
    
    # Cryptographic binding
    signature: str  # HMAC signed by RuntimeIdentityAuthority
    
    def validate(self, authority: 'RuntimeIdentityAuthority') -> bool:
        """Validate this identity against the trusted authority."""
        return authority.validate_identity(self)
```

## H. Private Invocation Envelope

### Role Determination

**Classification:** **CAPABILITY_CARRIER**

**Rationale:**
- Must transport canonical execution identity
- Must transport capability/lease
- Must provide provenance for learning
- Must be validated before consumption

**How to Obtain Capability:**
- Envelope is created by RuntimeIdentityAuthority
- Contains canonical execution identity (issued by authority)
- Contains capability/lease (issued by authority)
- Contains cryptographic signature (signed by authority)

**Where to Verify Real Capability:**
- At envelope consumption time
- Validate canonical execution identity against RuntimeIdentityAuthority
- Validate capability/lease against LeaseRegistry
- Validate cryptographic signature
- Only allow consumption if all validations succeed

### Redesigned Structure

```python
@dataclass(frozen=True)
class PrivateInvocationEnvelope:
    """Private invocation envelope carrying capability and provenance.
    
    This envelope is NOT fabricable by callers. It can ONLY be created
    by RuntimeIdentityAuthority and contains cryptographically signed
    capability and provenance information.
    """
    # Canonical identity
    canonical_identity: CanonicalExecutionIdentity
    
    # Capability/lease
    capability: InternalMcpInvocation
    
    # Provenance
    provenance: dict[str, Any]
    
    # Cryptographic binding
    signature: str  # HMAC signed by RuntimeIdentityAuthority
    
    def validate(self, authority: 'RuntimeIdentityAuthority') -> bool:
        """Validate this envelope against the trusted authority."""
        return authority.validate_envelope(self)
```

## I. Lease Architecture

### Correct Roles

**LeaseIssuerService:**
- **Responsibility:** Issue leases to validated processes
- **Input:** Validated canonical execution identity
- **Output:** InternalMcpInvocation lease
- **Validation:** Validates identity before issuing lease
- **Process binding:** Binds lease to process PID and incarnation
- **Expiration:** Sets expiration time
- **Signature:** Signs lease with HMAC

**LeaseRegistry:**
- **Responsibility:** Store and track leases
- **Input:** InternalMcpInvocation lease
- **Output:** None (storage only)
- **Validation:** Validates lease format before storage
- **Consumption tracking:** Tracks lease consumption (single-use)
- **Expiration tracking:** Tracks lease expiration
- **Stale invalidation:** Invalidates leases with old incarnation

### Lease Model

**Classification:** **CAPABILITY + AUTHORIZATION**

**Capability:**
- Grants permission to perform internal MCP invocation
- Binds to specific process and incarnation
- Has expiration time
- Is single-use

**Authorization:**
- Authorizes specific execution context (run_id, session_id)
- Authorizes specific producer scope
- Authorizes specific invocation

**Data:**
- Contains metadata for provenance
- Contains issuance timestamp
- Contains expiration timestamp

### Redesigned Structure

```python
@dataclass(frozen=True)
class InternalMcpInvocation:
    """Internal MCP invocation lease issued by trusted authority.
    
    This lease is NOT fabricable by callers. It can ONLY be created
    by LeaseIssuerService and is cryptographically bound to the
    canonical execution identity and process.
    """
    # Canonical identity
    canonical_identity: CanonicalExecutionIdentity
    
    # Process binding
    process_pid: int  # Actual process PID from OS
    runtime_incarnation: str  # Runtime incarnation at issuance
    
    # Authorization
    producer_scope: str
    invocation_id: str  # UUID, but issued by authority, not caller
    
    # Lifecycle
    issued_at_utc: datetime
    expires_at_utc: datetime | None
    consumed: bool = False
    
    # Cryptographic binding
    signature: str  # HMAC signed by LeaseIssuerService
    
    def validate(self, authority: 'LeaseIssuerService') -> bool:
        """Validate this lease against the trusted authority."""
        return authority.validate_lease(self)
```

- None

class InferenceService:
